## 关键设计要点

- **一次性 ticket + URL Query**:不把 JWT 放 URL,先调 `POST /api/ws/monitor-ticket`
  拿一次性 ticket,再连接 `ws://.../ws/monitor?ticket=xxx`。后端按 ticket 反查连接身份。
- **`MonitorWebSocket` 重连策略**:3 秒固定间隔重连,不指数退避(SPA 短会话场景下
  频繁可访问比背压更重要)。
- **`history-card` 顶栏** 显示采样条数,空数据时 `el-empty` 兜底。
- **`PageHeader` `actions` slot** 接管"实时连接"标签,布局与 ServerList/AdminUsers 一致。
- **`applyRealtime`** 不追加 history,只覆盖 `latest`,避免历史表被单条实时消息污染。
  `history` 仅由 `load()` 一次性 24h REST 拉取。

## 已知限制

- 后端 metrics 接口需 server Agent 在线才能产出数据;无 Agent 时历史表空 + 实时连接断。
- WebSocket 无心跳超时配置:实测如果 60 秒无消息浏览器仍认为连接存活。
- dark mode 下卡片主题不变。
