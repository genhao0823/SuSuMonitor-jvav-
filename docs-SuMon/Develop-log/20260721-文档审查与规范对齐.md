## 三、决策记录

### 3.1 方向调整

原决策：改后端对齐规范。
调整后：改规范对齐后端。

理由：
1. 后端代码已实现且测试通过（154+18 个测试）。
2. 协议文档 `websocket-protocol.md` 已写好，对齐后端实现。
3. 需求规范第 12.2 节已改对齐后端，项目实际已选择"规范对齐后端"方向。
4. 剩余只是命名差异（`request_id` vs `message_id`、`agent.register` vs `agent.authenticate`），不是功能差异。
5. 改规范文档比改代码安全，不影响已通过测试的代码。

### 3.2 AGENT_REGISTER_KEY 保留

决策：保留配置项，加注释说明"当前 WebSocket 鉴权不使用，保留供未来 Agent 自主注册流程"。

理由：后端 `application.yml` 有此配置项，虽 WebSocket 鉴权不读它，但保留不增加成本，为未来 Agent 自主注册流程预留。

### 3.3 Bug-fix 4 个只标注状态

决策：4 个 M4 Bug 只在 README 标注"未修复"，不在本次修复。

理由：本次聚焦文档对齐和 Go Agent 规划，Bug 修复另开任务。

### 3.4 Go Agent 技术栈

决策：Go 跨平台 Agent，不用 Java。

理由：Agent 是轻量采集探针，Go 单二进制零依赖、资源占用低（10-20MB），适合部署到每台被监控服务器。Java/JVM 重量级特性与采集器定位不匹配。
