## 设计决策

1. **新文件 `agent-token.ts` 而非塞进 `server.ts`**
   - OpenAPI 把 3 个端点归在 `servers` tag 但语义上属独立资源
   - `AgentTokenDialog.vue` 也需要独立模块
   - 符合"单一职责"原则,与现有 8 个 HTTP 模块边界一致

2. **明文 Token 不进 store**
   - 严格遵循后端"明文仅一次性返回"约定
   - 不进 Pinia store、不进 localStorage、不进 sessionStorage、不进日志
   - dialog 内 `el-alert` 显示 + 复制按钮;关闭时清空 + toast 提醒"已复制后请妥善保存"

3. **错误码映射复用既有字典**
   - SSH_HOST_KEY_NOT_CONFIRMED / SSH_HOST_KEY_MISMATCH / FORBIDDEN / UNAUTHORIZED / RESOURCE_CONFLICT / RESOURCE_NOT_FOUND 已存在于 `src/types/error-code.ts:6-23`
   - 无需新增错误码,纯映射逻辑

4. **撤销二次确认用 ElPopconfirm**
   - 与 `ServerDetailView` 已有的"删除"按钮模式完全一致
   - 避免引入新组件,降低 LONG_FILE 风险

5. **管理员权限硬控**
   - 4 个入口全部 `v-if="auth.isAdmin"`,与后端 `SecurityConfig.java:91-100` 的 `hasRole("ADMIN")` 对齐
   - 后端是最后防线,前端只是 UX 优化

6. **主机指纹走 ElMessageBox.prompt 而非新组件**
   - `inputPattern: /^SHA256:[A-Za-z0-9+/]{43}$/` 与 OpenAPI 契约严格一致
   - `replace` 字段不做 UI 切换(ElMessageBox 不支持复选框),把"轮换还是首次确认"决策权留给后端(`operation` 字段会回传 `confirmed` / `rotated` / `unchanged`)
   - 若管理员意图是轮换,服务端会自动判别并回 `rotated`,前端按回执显示中文提示
