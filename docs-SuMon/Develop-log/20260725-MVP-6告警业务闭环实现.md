## 一、目标

实现 MVP-6 告警业务闭环：规则 CRUD、状态机去重、记录查询、标记已读、恢复和 `alert.push` WebSocket 推送，暂不依赖 RabbitMQ，使用 Spring 本地事务事件。

出口条件：
- 首次越界生成告警
- 持续越界不重复
- 恢复后转为 `resolved`
- 再次越界生成新告警
- `alert.push` WebSocket 推送

## 三、MVP-6 告警模块（3 批次）

### 批次 1：V10 迁移 + 实体 + 枚举 + 状态机

- Commit：`b6c6da5`
- 12 文件

**V10 迁移**
- ALTER `alert_rules` 增加 `deleted` + `deleted_at` 软删除字段
- CREATE `alert_states` 表，`uk_alert_states_rule_server` 唯一约束 + `version` 乐观锁

**枚举**
- `AlertMetric`：cpu/memory/disk/temperature/load + `extract(MetricsLatestVo)` 字段映射
- `AlertOperator`：>/>=/</<= + `eval(BigDecimal, BigDecimal)` 比较
- `AlertLevel`：warning/critical
- `AlertRecordStatus`：unread/read/resolved

**Entity**
- `AlertRuleEntity`：映射 alert_rules（含 deleted/deleted_at）
- `AlertRecordEntity`：映射 alert_records
- `AlertStateEntity`：映射 alert_states（手动乐观锁，不用 @Version）

**AlertTransition**（sealed interface + 同文件 record）
- `Trigger`：首次越界，携带 rule + currentValue
- `ContinueBreached`：持续越界，携带 state + currentValue
- `Resolve`：恢复，携带 state
- `NoAction`：无操作

**AlertStateMachine**
- 纯逻辑评估器，不依赖数据库
- `evaluate(rule, metrics, currentState)` → `AlertTransition`

**修改 @MapperScan**
- 增加 `annotationClass = Mapper.class` 过滤
- 避免 sealed interface `AlertTransition` 被误扫描为 Mapper

**AlertStateMachineTests**：15 测试全部通过

  Trigger/ContinueBreached/Resolve/NoAction，发布 `AlertTriggeredEvent`
- `AlertTriggeredEvent`：record（serverId + AlertRecordVo）
