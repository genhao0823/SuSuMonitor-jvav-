# Apifox SSH 50002 真实验收

## 目标

执行 Apifox 测试用例 `397698534`，验证正确主机身份已登记后发生的 SSH TCP 连接拒绝会返回 HTTP `502`、业务码 `50002`。

## 场景控制

1. 独立 SSHD 仅监听 `127.0.0.1:2223`，生成临时 RSA 主机密钥。
2. 临时服务器通过业务接口创建，使用该 SSHD 的正确 SHA-256 指纹完成主机密钥登记。
3. 停止 SSHD，使后续 SSH test 在连接阶段被拒绝。
4. 使用真正无请求体的 `POST /api/servers/{id}/ssh/test` 运行 Apifox 用例。

该顺序排除了主机密钥不匹配和错误密码认证失败，因此覆盖的是 `CONNECTION_FAILED` 分类。

## 结果

```text
项目：8585366
分支：ai/20260725-from-main-ssh-50003-validation
用例：397698534
名称：J7 SSH connection refused returns 50002
```

JSON 报告结果为 `passed=1`、`failed=0`。JUnit 报告中的 4 项断言全部通过：

| 断言 | 结果 |
|---|---|
| HTTP status is 502 | 通过 |
| Business code is 50002 | 通过 |
| Message is ssh connection failed | 通过 |
| X-Request-ID exists | 通过 |

## 清理与边界

- 运行时 JWT 仅用于当前进程，并在 JSON/JUnit 报告中替换为 `[REDACTED_JWT]`。
- 本轮失败和成功尝试创建的临时服务器均只通过业务接口软删除，数据库复核删除字段均已写入。
- 验收结束后 `18080`、`2223` 均未监听，临时 SSHD 目录和 RSA 私钥均不存在。
- 本次只覆盖连接阶段失败 `50002`；错误密码认证失败 `50003` 见 `20260725-Apifox-SSH-50003-真实验收.md`。
