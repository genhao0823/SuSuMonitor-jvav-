# Java 终端控制帧限流

**日期**: 2026-07-26
**状态**: 已实现、单元测试通过；尚未进行 WSL 真实压测

## 目标

在 Java 单 JVM 的 Monitor 到 Agent 终端控制链路中限制 `terminal.open`、`terminal.input`、`terminal.resize` 与 `terminal.close`，防止单个浏览器连接或会话持续占用协议解析、会话服务和 Agent 写入资源。

## 实现

- 新增 `TerminalMessageRateLimiter`，使用 JVM 内存中的同步 Token Bucket，不引入 Redis 或第三方限流组件。
- `terminal.open` 按 Monitor WebSocket 会话限流；创建前没有服务端 `session_id`，不能按浏览器提供的值分桶。
- `terminal.input`、`terminal.resize`、`terminal.close` 按 Monitor WebSocket 会话与已经过协议校验的 `session_id` 独立分桶，避免一个终端耗尽同一浏览器其他终端的控制帧额度。
- 限流位于协议校验和 Agent 中继之间；超限控制帧不会下发 Agent，Monitor 收到稳定错误码 `42904 TERMINAL_MESSAGE_LIMIT_REACHED`。
- Monitor WebSocket 断开时释放所有关联桶，防止单 JVM 内存状态随断连连接增长。
- 参数从 `AppProperties.Terminal` 绑定并由 Jakarta Validation 限制为正数：
  - `TERMINAL_OPEN_RATE_PER_MINUTE=6`，`TERMINAL_OPEN_BURST=2`
  - `TERMINAL_INPUT_RATE_PER_MINUTE=600`，`TERMINAL_INPUT_BURST=120`
  - `TERMINAL_RESIZE_RATE_PER_MINUTE=60`，`TERMINAL_RESIZE_BURST=20`
  - `TERMINAL_CLOSE_RATE_PER_MINUTE=30`，`TERMINAL_CLOSE_BURST=10`
