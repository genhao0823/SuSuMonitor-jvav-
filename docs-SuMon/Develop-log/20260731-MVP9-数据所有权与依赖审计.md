## 一、数据所有权矩阵（现状）

| 数据表 | 所属模块 | 唯一写入方 | 跨模块读取方（审计前） |
|---|---|---|---|
| `users` / `auth_bootstrap_state` | auth | auth.UserServiceImpl | **admin**（审核）、**terminal**（approved 校验） |
| `servers` | server | server.ServerServiceImpl | **metrics**（FOR UPDATE 存在性校验）、**terminal**（存在/Agent 在线校验） |
| `metrics` / `metrics_ingestions` | metrics | metrics.MetricsServiceImpl | alert（经 `MetricsReportedEvent` + `MetricsLatestVo`，事件契约） |
| `alert_rules` / `alert_records` / `alert_states` | alert | alert.*ServiceImpl | 无 |
| `terminal_sessions` | terminal | terminal.TerminalSessionServiceImpl | 无 |
| `commands`（V4） | 无（孤儿表） | — | 无 Java 代码引用 |
| `ssh_sessions`（V6） | 无（孤儿表） | — | 无 Java 代码引用 |

模块间事件协作（不属于表访问）：metrics → alert 通过 `MetricsReportedEvent`（AFTER_COMMIT 本地事务事件，MVP-10 将替换为 `metrics.reported.v1` 消息）。

## 二、审计发现（3 处跨模块 Mapper 直接访问）

| # | 访问方 | 目标 | 用途 | 处置 |
|---|---|---|---|---|
| 1 | module.admin | auth.UserMapper | 审核列表/审核状态更新 | **收口**：改走 `UserService.listPendingUsers/getReviewUserById/updateReviewStatus` |
| 2 | module.metrics | server.ServerMapper | `selectActiveServerForUpdateById` 行锁校验 | **收口**：改走 `ServerService.existsActiveForUpdate`（FOR UPDATE 语义封装在 server 模块） |
| 3 | module.terminal | auth.UserMapper + server.ServerMapper | approved 校验 + 服务器存在/Agent 在线校验 | **收口**：改走 `UserService.isApprovedUser` + `ServerService.existsActive/isAgentOnline` |

## 三、收口后契约

**auth.UserService 新增**：
- `List<UserEntity> listPendingUsers()` — 管理面审核列表
- `UserEntity getReviewUserById(Long)` — 审核前置校验
- `boolean updateReviewStatus(Long, String, Long, LocalDateTime)` — 审核状态更新（0 行返回 false）
- `boolean isApprovedUser(Long)` — 已审核通过校验（终端等能力校验）

**server.ServerService 新增**：
- `boolean existsActiveForUpdate(Long)` — 事务内 FOR UPDATE 行锁存在性校验（指标接收强一致路径）
- `boolean isAgentOnline(Long)` — 存在且 Agent 在线校验（终端能力校验）

业务归属不变：审核业务逻辑仍在 admin 模块，指标接收业务仍在 metrics 模块，仅**数据访问统一走数据所有者的 Service 契约**。

## 五、遗留项与建议

1. **`commands`（V4）、`ssh_sessions`（V6）孤儿表**：无 Java 代码引用。建议 MVP-8 阶段决策：保留作预留（当前倾向）或 V14 迁移删除；不推荐无主表长期存在。
2. **alert 模块读取 metrics 的 `MetricsLatestVo`**：经事件契约传递，属模块间通信而非表访问，MVP-11 拆分后由 `metrics.reported.v1` 消息 payload 替代，符合冻结契约。
3. **`AGENT_REGISTER_KEY` 占位项**：配置已定义但无消费方，随 MVP-10 Agent 注册流程推进时再决策。
4. **单 JVM 内存注册表**（`AgentConnectionRegistry`/`MonitorSubscriptionRegistry`/`TerminalRelayRegistry`）：多实例前需 Redis 共享，属 MVP-10+ 范围。
5. **Monitor WS 授权**：当前 approved/admin 可订阅任意服务器，`MonitorWebSocketHandler` 注释已留痕，按服务器粒度收紧属后续增强。
