## 三、关键发现 + 修复:旧 vite 进程占用 5173

### 症状

第一轮用 `admin/1059412135` 在浏览器登录后,被重定向到 `/forbidden`,toast 报"账户尚未通过审核"。但 curl 同一接口返回 200 + role=admin + reviewStatus=approved。

### 排查

1. 后端日志 + curl 三次重试均稳定 200,排除后端问题
2. 检查 5173 端口:`netstat -ano` 发现 **PID 15476 在 5173 监听**(本会话外的旧 vite)
3. 当前会话启动的新 vite 日志显示 `Port 5173 is in use, trying another one... 5174`
4. 两个 vite 同时存在,但**前端代码可能不同**(旧 vite 跑的是 pre-B-038 的代码)

### 修复

```bash
taskkill //PID 15476 //F
# 终止当前 5174 vite 进程,重启新 vite
# 重启后 vite 监听 5173,与 OpenAPI + B-038 提交代码一致
```

### 验证

- 重启后 vite 日志:`➜ Local: http://127.0.0.1:5173/`
- IAB 浏览器登录 `admin/1059412135` → URL 跳到 `/dashboard`(不再跳 `/forbidden`)
- Dashboard 完整渲染:服务器总数 = 24,管理员 + 已通过 badge,5 个菜单项

### 教训

本机/会话反复 `npm run dev` 容易留下僵尸 vite 进程占用默认端口,**新 vite 静默 fallback 到 5174**;新代码与旧 vite 实例冲突时表现为难以察觉的逻辑异常。**下次启动 dev 前先 `taskkill /IM node.exe /F` 或 netstat 检查 5173**。
