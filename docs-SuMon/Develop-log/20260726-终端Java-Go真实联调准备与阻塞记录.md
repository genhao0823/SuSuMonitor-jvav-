## 已实现的联调链路

1. 浏览器通过 `/ws/monitor` 发送 `terminal.open`，参数为 `server_id`、`cols`、`rows`。
2. Java 回查当前 `review_status=approved`，创建持久化元数据并生成 `session_id`。
3. Java 向已认证 `/ws/agent` 注入持久化 `server_id`、生成的 `session_id`，下发 `terminal.open`。
4. Go Agent 校验下行 `server_id` 与本地配置相同，使用本地固定 Shell 创建 PTY。
5. Agent 的 `opened/output/closed/error` 经过 Java 服务器和会话归属校验，仅回送创建会话的 Monitor WebSocket。
6. Monitor 或 Agent 断开时，Java 收口路由与元数据；Monitor 断开会尝试下发 `terminal.close`。

## 隔离环境执行清单

在短生命周期 Linux 测试主机或容器中，通过环境变量安全注入以下值，不写入仓库文件或命令行：

- Java：`DB_NAME=susumonitor_metrics_validation`、`DB_USER`、`DB_PASSWORD`。
- Go Agent：`SUSUMONITOR_BACKEND_URL`、`SUSUMONITOR_SERVER_ID`、`SUSUMONITOR_AGENT_TOKEN`、`SUSUMONITOR_TERMINAL_ENABLED=true`、受控 `SUSUMONITOR_TERMINAL_SHELL`。

执行顺序：

1. 备份隔离数据库并验证备份存在、非空且可读取。
2. 使用 `mvn -Pmysql-validation verify` 验证 V12 和终端元数据迁移。
3. 启动 Java 服务与单个 Linux Go Agent，确认 `/ws/agent` 完成认证。
4. 以 approved 测试用户建立 `/ws/monitor`，发送 `terminal.open`，断言接收 `opened`。
5. 发送 Base64 `terminal.input`，断言同会话收到对应 `terminal.output`；检查 Java 日志、数据库和 Git 记录均不出现 PTY 内容。
6. 发送 `terminal.resize`，再发送 `terminal.close`，断言 `closed` 和元数据关闭。
7. 分别断开 Monitor 和 Agent，验证 PTY 收口及会话状态为 `closed` 或 `error`。
8. 验证跨 Agent `server_id` 冒充、非 approved 用户、超额会话和超限载荷均被稳定错误码拒绝。

## 后续风险

- Java 中继目前是单 JVM 内存路由，不支持多实例故障转移。
- 终端帧尚未使用独立于既有 Agent Metrics 限流器的配额；真实压测前需确定消息速率、输出带宽和浏览器慢消费者阈值后再实现，避免任意引入未验证的默认参数。
