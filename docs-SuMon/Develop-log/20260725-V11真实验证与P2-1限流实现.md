# V11 真实验证与 P2-1 限流实现

**日期**: 2026-07-25
**范围**: Java 后端 Metrics 真实 MySQL 验证、Agent WebSocket 资源边界。

## V11 真实 MySQL 验证

- 创建隔离库 `susumonitor_metrics_validation`，不修改 `susumonitor` 开发库。
- Flyway 在 MySQL 8.4 真实执行并验证 V1-V11。
- `MetricsIngestionMySqlValidationIT` 通过，覆盖重复 UUID 幂等、事务回滚和同服务器并发顺序。
- 实际运行时发现 Spring 6.2 拒绝 `@TransactionalEventListener` 与默认 `@Transactional` 组合；告警评估器改为 `REQUIRES_NEW`，与其独立事务设计一致。

## P2-1 实现

- 配置 Agent 单 JVM 总连接 128、未认证连接 32、每 IP 握手 10/min、心跳 12/min burst 3、Metrics 24/min burst 6。
- 总连接与未认证连接通过 `AgentConnectionLimiter` 原子管理，连接关闭释放配额。
- 已认证会话通过独立 Token Bucket 限制 heartbeat 与 metrics.report；超频返回 `42902` 后关闭 `1008`。
- Upgrade 前通过 `AgentHandshakeInterceptor` 限制单 IP 握手，超限返回 HTTP 429 和 `Retry-After: 60`。
- 仅可信代理 CIDR 可使用 X-Forwarded-For，按右向左剥离代理地址；直连请求忽略伪造转发头。

## 验证

- `mvn -Pmysql-validation verify`：真实 MySQL IT 11 通过，0 失败。
- P2-1 定向测试：30 通过，0 失败。
- `api-test/run-p2-agent-e2e.ps1`：隔离 MySQL、Java `18081` 与真实 Go Agent 联调通过。
- Go Agent 验证 4 项通过：有效 Token 在连接配额门控期间按 1 秒、2 秒指数退避；释放门控后完成认证。
- P2 WebSocket 验证 4 项通过：`42901 + 1008`、heartbeat `42902 + 1008`、Metrics `42902 + 1008`、单 IP Upgrade HTTP `429`。
- 真实联调发现连接建立回调内同步发送 error 后立即关闭会丢失错误帧；改为 50ms 后关闭，保证客户端先收到 `42901` 或 `42902`。
- Go Agent 完整退避验证 6 项通过：在连接配额门控下实际记录并断言 `1s -> 2s -> 4s` 退避序列及相邻最小等待时间，释放门控后重新认证。
- Go Agent 服务恢复与 Token 轮换验证 6 项通过：已认证 Agent 在 Java 服务停止后检测断连并按退避重试，服务恢复后自动重新认证；轮换 Token 后旧 Token 重连持续被拒绝，使用新 Token 的 Agent 可以认证。
- 恢复场景使用独立的 Java `18082` 实例，不影响 `18081` 限流验收实例；两个实例均连接隔离 MySQL。
