## 目的

验证后端 `/api/admin/users/{id}/approve` 与 `/reject` 在用户已被审核(状态非 pending)
时**确实**返回 OpenAPI 契约规定的 `40900 RESOURCE_CONFLICT`,从而前端
`AdminUsersView.explainError` 的错误码映射在真实并发或后端状态异常时可被触达。

## 关键结论

1. **后端按 OpenAPI 契约行为完全正确**
   - 重复 approve → 409 + 40900
   - approve 后 reject → 409 + 40900
   - 状态机一致:`pending → approved/rejected` 后不再可操作

2. **前端 `AdminUsersView.explainError` 映射可被触达**
   - 静态检查:`grep "RESOURCE_CONFLICT" src/views/AdminUsersView.vue` 已确认
   - 字符串映射:`40900 → "该用户已被审核,请刷新列表查看最新状态"`
   - 一旦真实并发或后端状态异常触达,前端能正确 toast

3. **常规 UI 流程仍无法触达该代码路径**
   - 列表只显示 pending,approve 后 reload → 行物理消失
   - 按钮无法再次点击
   - 真正弹窗测试需要:多端并发、E2E 测试、或后端人工改库
