# 开发日志: Web 前端认证持久化策略决策

**日期**: 2026-07-22

**操作人**: opencode

## 决策结论

Web 前端保留登录页“记住我”选项，并继续使用 `localStorage` 作为可选的认证持久化介质：

- 勾选“记住我”时，将 JWT 和最小用户快照写入 `localStorage`，允许刷新页面和重新打开浏览器后恢复登录。
- 未勾选“记住我”时，JWT 只保留在当前 Pinia 内存状态，不写入 `localStorage`；刷新或关闭页面后需要重新登录。
- 未勾选时的当前页面仍必须正常携带 Authorization，axios 不能只从 `localStorage` 读取 Token。
- 退出登录、HTTP 401 和认证恢复失败时，必须同时清理 Pinia 认证状态和 `localStorage` 认证项。

该决策不修改后端 JWT、REST API、OpenAPI 或 WebSocket 协议。

## 安全边界

- `localStorage` 可被同源 JavaScript 读取，不能防御 XSS，且勾选“记住我”会延长 Token 暴露周期。
- 持久化白名单只允许 JWT 和最小用户快照，不保存密码、SSH 密码、私钥、passphrase、Agent Token 或其他凭据。
- 前端不得在 URL、console、错误消息、测试输出或开发文档中记录真实 Token。
- 后端 JWT 过期、用户审核状态和接口权限校验仍是最终安全边界。
- 前端通过依赖审计、禁止未审计第三方脚本、退出/401 立即清理降低风险；严格 CSP 留待部署阶段实施。

## 代码影响

后续 F1 认证模块需要检查并测试：

- `web-vue-SuMon/src/stores/auth.ts`：根据“记住我”决定是否持久化。
- `web-vue-SuMon/src/api/client.ts`：支持当前内存 Token 和持久化 Token，避免未勾选时丢失 Authorization。
- `web-vue-SuMon/src/main.ts`：冷启动时只对已持久化会话执行认证恢复。
- `web-vue-SuMon/src/router/guards.ts`：认证初始化完成后再判断登录和角色。
- `web-vue-SuMon/src/views/LoginView.vue`：保留“记住我”，防止重复提交。
- `web-vue-SuMon/src/views/RegisterView.vue`：注册提交保持单次触发。

## 验收要求

- 勾选“记住我”登录后，刷新和重新打开浏览器可以恢复登录。
- 未勾选时，登录后的当前页面 API 正常携带 Authorization；刷新后跳转登录页。
- 退出、401 和认证恢复失败后，内存状态与 `localStorage` 认证项均被清理。
- `localStorage` 中不出现密码、SSH 凭据、私钥或 passphrase。
- 自动化测试覆盖两种“记住我”分支、请求头注入和清理路径。
