## 目标

实现 MVP-7 T4 前端 Web 终端 **最小可用版本**:
- 浏览器通过 `/ws/monitor` channel 复用 socket,发送 `terminal.open/input/resize/close` 控制帧
- 接收 `terminal.opened/output/closed/error` 响应
- xterm.js 显示 PTY 输出 + 键盘输入回传
- ServerList/Detail 加"打开终端"入口
- 仅 approved 用户可开启(后端再校验 40302)

## 范围外(明确不做)

- session 历史记录、活跃 session 列表、多 tab 切换
- 附件上传/下载
- 主题切换、字体自定义(用 xterm 默认深色)
- 主动重连(`MonitorWebSocket` 现有 3 秒重连机制下,session_id 已失效,需手动重试)
- openapi-typescript 自动生成(ECharts 接入等同属基础设施升级,独立计划)

## 设计决策

1. **复用 `/ws/monitor` channel,不另开 WebSocket**
   - 协议文档明文允许 metrics + terminal 共用 `/ws/monitor`
   - 避免双 ticket 申请、双 socket 维护、双重连 timer

2. **onSocketReady 在 metrics.subscribe 之前触发**
   - TerminalWebSocket 需要在 socket OPEN 拿到实例并立即发 `terminal.open`
   - 但 `metrics.subscribe` 也必须在 socket OPEN 后发出
   - 顺序:onopen → onSocketReady(订阅者建 TerminalWebSocket) → metrics.subscribe

3. **断线不自动重连**
   - 后端 session_id 与 WebSocket 连接绑定,socket 断则 session 失效
   - 自动重连会产生新 session_id,前端无法把旧 PTY 输出流对上
   - 由 UI 提供"重试"按钮,完整重建 MonitorWebSocket + TerminalWebSocket

4. **Base64 + UTF-8 编码**
   - 协议层 1-16 KiB 上限,UTF-8 文本足够
   - 用浏览器原生 `btoa`/`atob` + `TextEncoder`/`TextDecoder`,零依赖

5. **菜单入口用 ElMessageBox.prompt 而非新组件**
   - 避免引入新的 server 选择器组件
   - MVP 阶段:用户输 serverId(列表中可查)→ 跳路由
   - 后续若用户量增大,可替换为 el-select 弹出层

6. **approved 权限校验放在 view 与按钮双重**
   - 按钮 `v-if="auth.isApproved"` 控制可见性
   - view 顶部再校验一次 `auth.isApproved`,防止 URL 直达
   - 后端 40302 兜底(满足协议 §Security 要求"每次控制帧重新查 review_status")
