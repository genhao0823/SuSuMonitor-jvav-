## 执行前置条件

真实 MySQL 集成测试必须显式设置：

```text
RUN_MYSQL_VALIDATION_TESTS=true
DB_HOST=127.0.0.1 或 localhost
DB_NAME=<名称包含 validation 的隔离库>
DB_USER=<隔离库用户>
DB_PASSWORD=<通过环境变量注入>
```

脚本的真实 HTTP/WebSocket 运行还要求：

```text
SUSUMONITOR_VALIDATION_BASE_URL=<运行中的隔离服务地址>
SUSUMONITOR_VALIDATION_ADMIN_USERNAME=<管理员用户名>
SUSUMONITOR_VALIDATION_ADMIN_PASSWORD=<通过环境变量注入>
```

脚本会通过业务 API 创建临时用户、服务器、Agent Token、告警规则、指标与告警记录。运行前必须确认服务连接到隔离验证库，不能指向共享或生产数据库；token、密码、ticket、Agent token 和完整原始消息不会写入脚本输出。

## 推荐执行顺序

1. 在隔离 MySQL 库完成可读且非空的备份，并记录当前 Flyway 版本。
2. 设置 `RUN_MYSQL_VALIDATION_TESTS=true` 与隔离 `DB_*` 环境变量，运行 `mvn -Pmysql-validation verify`。
3. 启动连接该隔离库的后端，确认 `/api/health` 和 `/api/ready` 正常。
4. 设置 `SUSUMONITOR_VALIDATION_*` 环境变量，运行 `npm --prefix api-test run verify:alert-ws`。
5. 在浏览器执行一次重复规则创建，确认 HTTP `409/40900` 对应既有中文 toast。
6. 分别记录 MySQL、HTTP、WebSocket 和浏览器层的实际结果；未覆盖项保持“未验证”，不以单元测试替代。
