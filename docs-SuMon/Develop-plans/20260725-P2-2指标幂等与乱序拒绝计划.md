# 开发计划: P2-2 指标幂等与乱序拒绝

**日期**: 2026-07-25
**状态**: 已完成

## 目标

为 Agent `metrics.report` 固化至少一次投递语义：同一 `server_id` 与 `message_id` 的重复投递静默幂等；采样时间小于或等于该服务器最后接受采样的消息被拒绝，不写入指标、不发布事件。

## 任务清单

- [x] 新增 V11 指标投递去重表及唯一索引。
- [x] 在指标写入事务中锁定服务器行，串行化同一服务器的乱序判定。
- [x] 校验 UUID message_id，处理重复投递和严格乱序拒绝。
- [x] 更新 Agent WebSocket 协议和 HTTP 调试样例。
- [x] 增加 Service 与 Handler 边界测试并完成验证。

## 预期时间

预计 1 个开发批次完成。

## 依赖关系

- 依赖现有 V3 `metrics` 表、Agent WebSocket 首帧认证和 Metrics AFTER_COMMIT 事件。
- 不依赖 Go Agent、前端页面、Redis 或 RabbitMQ。

## 备注

- 同时间戳使用 `<=` 判定为乱序，保证 accepted metrics 的 `collected_at` 严格递增。
- 不新增 `metrics.report.ack`；重复投递静默幂等，Agent 仍由自身重试超时控制。
- V10 已用于告警状态，指标去重迁移顺延使用 V11。
