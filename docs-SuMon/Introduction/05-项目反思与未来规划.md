## 二、未验证 / 待办（按重要性排序）

> 这些是**代码已实现但未在本机真实公网 / 多实例 / 大规模场景跑通**的事项，与 README "未验证" 一致。

### 优先级 1：**首管理员空库并发真实压测**
- **现状**：V7 行锁已实现，单元测试全过，但**真实 1000 并发抢注首个 admin**没压过。
- **缺口**：突发账号注册雪崩可能短暂锁等待。
- **计划**：用 k6 / JMeter 跑 1000 并发 POST `/api/auth/register`，观测平均 / P95 延迟与失败率。

### 优先级 2：**公网真实 HTTPS / WSS 部署**
- **现状**：Nginx 反代模板、CA 证书、systemd Unit 都已就绪。**域名备案中**。
- **缺口**：生产 CA 证书、TLS 1.3 配置、HSTS / OCSP Stapling 没真实验证。
- **风险**：宽带运营商可能劫持未加密 HTTP 头（参见 `Difficulty-log/20260730-宽带运营商劫持WebSocket-诊断记录.md` 当时 curl 抓包确认）。
- **计划**：域名备案完成后按 `Handoff-SuMon/20260727-云端T5部署交接.md` 一键部署。

### 优先级 3：**多 JVM 实例下 AFTER_COMMIT 事件跨实例推送**
- **现状**：`MonitorTicketService` / `AgentConnectionRegistry` / `TerminalRelayRegistry` / `MonitorSubscriptionRegistry` 全部为**单 JVM 内存**。
- **缺口**：横向扩容时 Agent 的 WS 连接和 订阅者可能在不同实例，事件不会跨实例广播。
- **计划**：引入 Redis Pub/Sub 把 "MetricsReportedEvent" 在 N 个实例间共享；终端中继也上 Redis Registry。

### 优先级 4：**Agent Linux 二进制真实公网 WSS 长连**
- **现状**：`Makefile build-linux` 已加，二进制 `bin/susumonitor-agent-linux-amd64` 已编译；本机 VM 测试过，但**真实公网家庭 Linux 路由器 NAT 环境**下未跑过。
- **缺口**：NAT 穿透、长连接保活、运营商劫持。

### 优先级 5：**Monitor 1012 真实背压覆盖**
- **现状**：单元测试 34 项覆盖慢消费者，**真实浏览器 1MB/s 输出压测**未做。
- **计划**：用 `puppeteer-core` 脚本制造慢消费场景，断言 5s/256KiB 阈值生效 + SESSION_NOT_RELIABLE 关浏览器行为。

### 优先级 6：**MV-9 Java 后端性能基线**
- **现状**：测试场景已建立（单服务器 1000 规则 / 多服务器并发 / 持续越界 / 重复 message_id 比例 / Monitor 订阅数变化），**数字尚未执行**。
- **指标口径**：必须包含 p50 / p95 / p99 + 异常率，禁止只报告平均。
- **计划**：用 JMeter 跑 24h 压测，输出基线报告。

### 优先级 7：**真实 Alert 端到端（千条 record + 恢复链路）**
- **现状**：Apifox 30 断言 + 单 record 路径全过；**10000 条 record 列表性能 + 状态机正确性**未压。
- **计划**：seed 大量规则 + 大量越界事件，验证 alert_states 乐观锁在并发下的最终一致性。

### 优先级 8：**LONG_FILE 拆分第二轮（3+ 千行单文件）**
- **现状**：第一轮已拆 `MetricsServiceImpl` 等；后续若有再次膨胀的类需跟进。

## 四、反思：项目过程中的 "教训 + 收获"（按主题）

### 教训 1：MockMvc 全绿 ≠ 真实 SQL 没问题

**事件**：`AlertRuleMapper.insertRule` 缺 `@Param("rule")` 注解 + `keyProperty="rule.id"` 配置不匹配，所有 MockMvc 单元测试都过，但**真实 MySQL 跑 POST/PUT/DELETE** 时返 500 空 body。

**教训**：单元测试 mock 链路全过不能保证 SQL 真实可执行。**必须配 H2 真实 SQL 集成测试 + `*IT.java` 真实 MySQL 双轨**。

**整改**：新增 `AlertRuleMapperMybatisTests` H2 子集跑真 INSERT/UPDATE/软删；同时跑 `AlertRuleMySqlValidationIT` 连真 MySQL 复验。

**文档**：`Bug-fix/2026-07-27-MVP6-alert-rules-mapper-500.md`。

### 教训 2：前端的 try/catch 静默吞错隐藏业务问题

**事件**：`stores/alerts.ts` 的 3 个 action 在 `catch` 里返回 `null/false` 而非重抛，导致 `AlertRuleDialog` 双层 try/catch 的精确错误码映射永远不可达。前端用户看到成功 toast，实际请求 500。

**教训**：Error Handling 必须是显式的，要么完整重抛，要么明确状态管理；**前端开发者应当把"catch 不抛"当成 bug**。

**整改**：catch 设 `rulesError` + **重抛原 error**，返回类型收紧为 `Promise<AlertRule>`，dialog outer catch 接管。

**文档**：`Bug-fix/2026-07-27-MVP6-alert-store-swallows-error.md`。

### 教训 3：单 JVM 内存假定让我"过早抽象"

**事件**：`MonitorSubscriptionRegistry` / `TerminalRelayRegistry` 用 `ConcurrentHashMap`，本机跑通，但多实例时完全失效。

**教训**：抽象不应当把"单 JVM"作为隐式前提。**演进路径要明确写在 README**：当前单 JVM，多实例时改 Redis 共享。

**整改**：所有 Registry 类都加 `@ConditionalOnProperty(name = "susumonitor.ha.enabled", havingValue = "false")`，留演进接口。

### 教训 4：监控端慢是隐形杀手

**事件**：MVP-7 终端第一版没有背压，测试时浏览器切到后台 30 秒后回前台，前端花 10 秒才响应（因为 JVM 在拼命给单个 session 发数据）。

**教训**：**长连接 + 多客户端**应用必须设计"主动断开慢消费者"策略，否则生产环境一旦出现就会内存爆炸。

**整改**：所有 Monitor WS session 都用 `ConcurrentWebSocketSessionDecorator(TERMINATE)` 包裹；溢出即 1012 关。

### 教训 5：表格测试 vs 真实"集成"测试

**事件**：开发期间跑 OpenAPI 契约对比 mvn test 没问题；可发布到预览环境后因为请求 Content-Type 不对返 415。

**教训**：测试金字塔必须**单元 + 集成 + 契约 + e2e 全层次覆盖**。任何一层缺了就有盲区。

**整改**：补 `api:e2e` + `ui:e2e` + `audit:catchup` 4 道防线。

### 教训 6：环境差异比想象中多

**事件**：本机 Java 21 + WSL Ubuntu 22.04，部署到 OpenCloudOS 9.6 时 systemd 单元路径不一致、sshd_config 默认关闭密码登录、`/etc/susumonitor` 目录权限。

**教训**：**本机闭环 ≠ 部署闭环**；必须分环境配脚本 + 真实部署演练。

**整改**：`docs-SuMon/Handoff-SuMon/20260727-云端T5部署交接.md` 详细列出"已完成 / 待域名 / 注意事项"三段。

## 六、被问到 "你最大的收获是什么" 时的高密度回答

> 备用面试稿：

**最大收获可以从这 4 个维度讲：**

1. **从 Demo 到生产**：通过本项目学会了"工程化"——统一响应 / 错误码 / 请求追踪 / 配置分层 / 时钟注入 / 密钥启动期校验这些"不起眼但缺一不可"的基础设施。
2. **事务边界与副作用一致性**：从"`ws.sendMessage` 直接在 `@Transactional` 方法内调用"到"`@TransactionalEventListener(AFTER_COMMIT)`"，学到了"业务副作用必须在事务提交后才能发出"这个分布式系统入门道理。
3. **业务一致性的三件套**：状态表 + 乐观锁 + 唯一索引；NULL 用生成列转具体值；MyBatis 缺 `@Param` 让单元测试全绿但生产 500；这些都不是任何教科书会教的。
4. **真实集成测试的力量**：WSL 受控 SSHD `127.0.0.1:2223`、隔离 MySQL `*IT.java`、Apifox 27 断言、浏览器 IAB 联调——这些"麻烦但必须做"的步骤让项目从 Demo 变成可演示系统。
