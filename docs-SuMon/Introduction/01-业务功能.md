## 模块 M1：用户与权限

### 1. 业务目标

提供完整账号体系：注册 → 审核 → 登录 → JWT 鉴权 → 角色权限（admin / user）。首管理员通过行锁自动初始化。

### 2. 关键实体

#### `users` 表（Flyway V1 `create_users_table.sql`）

|---|---|---|---|---|---|
| `id` | BIGINT UNSIGNED | 否 | AUTO_INC | PK | 主键 |
| `username` | VARCHAR(64) | 否 | — | UNIQUE `uk_users_username` | 登录名 |
| `password_hash` | VARCHAR(255) | 否 | — | — | BCrypt 哈希（cost=10） |
| `role` | VARCHAR(16) | 否 | `'user'` | `idx_users_role` | `admin` / `user` |
| `review_status` | VARCHAR(16) | 否 | `'pending'` | `idx_users_review_status` | `pending` / `approved` / `rejected` |
| `reviewed_by` | BIGINT UNSIGNED | 是 | NULL | — | 审核人 user_id |
| `reviewed_at` | DATETIME | 是 | NULL | — | 审核时间 |
| `created_at` / `updated_at` | DATETIME | 否 | NOW() | — | 时间戳 |

#### `auth_bootstrap_state` 表（Flyway V7 `create_auth_bootstrap_state.sql`）

| 字段 | 类型 | 默认 | 含义 |
|---|---|---|---|
| `id` | TINYINT | 1（固定 PK） | 单行表 |
| `admin_initialized` | TINYINT(1) | 0 | 是否产生过 admin |
| `updated_at` | DATETIME | NOW() | 状态变更时间 |

### 3. 实现流程

#### 注册流程（`UserServiceImpl.register`，行号见 `module/auth/service/UserServiceImpl.java`）

1. **加行锁查 bootstrap state**：`SELECT ... FROM auth_bootstrap_state WHERE id=1 FOR UPDATE`，事务内禁并发；
2. **判断是否首位**：若 `admin_initialized=0`，本次注册用户自动获得 `role=admin + review_status=approved`；否则按 `user + pending`；
3. **BCrypt 哈希密码**：调用 `BCryptPasswordEncoder.encode(rawPwd)`；
4. **写 users 行 + 回填 state**：事务提交后写 `admin_initialized=1`；
5. **锁释放**：事务结束即释放（行锁粒度 = 单行）。

#### 登录流程（`UserServiceImpl.login`）

1. **用户名查 DB** → 若不存在，仍跑一遍 `passwordEncoder.matches(rawPwd, dummyHash)` 对齐耗时（**防时序探测**）；
2. **校验 review_status=approved 且 role ∈ {admin, user}**，否则返 `FORBIDDEN(40300)`；
3. **BCrypt 校验密码**；
4. **签发 JWT**：HS256、72h、payload 含 `iss/aud/sub(userId)/jti(UUID)/iat/exp/username`；
5. **返回 `LoginVo { token, tokenType: "Bearer", expiresIn }`**。

#### JWT 过滤器（`security/JwtAuthenticationFilter.java`）

```java
// security/JwtAuthenticationFilter.java (简化)
@Override
protected void doFilterInternal(HttpServletRequest req, HttpServletResponse resp, FilterChain chain) {
    String token = extractBearer(req);                       // 1) 解析 Authorization: Bearer
    if (token == null) { chain.doFilter(...); return; }     // 公开路径放行
    try {
        AuthenticatedUser user = jwtTokenService.parse(token);  // 2) 验签 + 解析
        UserEntity dbUser = userService.findById(user.id());    // 3) 每次回查 DB 最新审核态
        if (dbUser.getReviewStatus() != APPROVED) reject();     // 4) 撤销审核即刻生效，无需黑名单
        UsernamePasswordAuthenticationToken auth = new UsernamePasswordAuthenticationToken(
            user, null, List.of(new SimpleGrantedAuthority("ROLE_" + dbUser.getRole())));
        SecurityContextHolder.getContext().setAuthentication(auth);
    } catch (JwtException e) { reject(...); }
    chain.doFilter(req, resp);
}
```

关键技巧：`SecurityConfig` 里把这个 filter 用 `FilterRegistrationBean.setEnabled(false)` 关闭 servlet 自动注册，只走 security chain，**避免每请求验签两次**。

### 7. 可深入追问

1. **为什么 JWT 而非 Session？** 无状态、易横向扩展、跨域友好，代价是注销需黑名单或回查 DB（项目选了回查 DB）。
2. **为什么每请求回查 DB？** 用户被审核撤销 / 角色降级时立即生效，避免 JWT 黑名单维护成本。
3. **BCrypt vs scrypt / argon2？** Spring Security 默认，cost=10 在普通服务器上 < 100ms，未来上 argon2 改 hash 算法即可。
4. **Spring Security 怎么避免双重 filter？** `FilterRegistrationBean.setEnabled(false)` 是 Spring Security 官方推荐的"我只让 Spring Security 管我的 filter" 的写法。

### 3. 实现流程

#### 3.1 创建服务器 + 凭据加密（`ServerServiceImpl.create`）

1. 参数校验：Bean Validation `@Valid` + Controller 入口先 `existsActive(host)` 避免脏数据；
2. 加密凭据：`CredentialCipher.encrypt(raw, AAD)`，AAD 形如 `susumonitor:server:<newId>:credential:password`（按服务器 ID 绑 AAD 防密文重放）；
3. 写库 → 返回 `ServerVo`。

```java
// security/CredentialCipher.java (简化)
public String encrypt(String plain, String aad) {
    byte[] nonce = secureRandom.nextBytes(12);
    Cipher c = Cipher.getInstance("AES/GCM/NoPadding");
    c.init(ENCRYPT_MODE, key, new GCMParameterSpec(128, nonce));
    c.updateAAD(aad.getBytes(UTF_8));                  // 关键：AAD 防止同 nonce 重放到其他上下文
    byte[] ct = c.doFinal(plain.getBytes(UTF_8));
    return "v1:" + b64(nonce) + ":" + b64(ct);        // 带回版本前缀，便于将来升级
}
```

### 7. 可深入追问

1. **AES-GCM vs AES-CBC + HMAC？** GCM 自带认证，避免手动管理 IV 和完整性；密钥从环境变量注入。
2. **为什么行锁的 delete_token 而不是延迟删？** 删除是低频操作，行锁开销可忽略；好处是同一 host 可立即被重建。
3. **为什么用 sshj 而不是 Apache MINA SSHD？** sshj 是客户端库，本项目只测连接不需要搭服务端。
4. **agent_token 为什么 SHA-256 哈希存？** Token 高频比对；BCrypt 慢哈希会拖慢 agent 心跳链路。

#### 3.2 Java `/ws/agent` 通道（`websocket/AgentWebSocketHandler.java`）

```java
// websocket/AgentWebSocketHandler.java (简化)
@Override
public void afterConnectionEstablished(WebSocketSession session) throws Exception {
    sessionRegistry.putUnauth(session.getId(), session);              // 1) 先入未鉴权池
    if (!connectionLimiter.tryAcquire()) {                            // 2) 总限流 (128/未鉴权32)
        session.close(CloseStatus.POLICY_VIOLATION);
        throw new BusinessException(AGENT_CONNECTION_LIMIT_REACHED);
    }
    handshakeLimiter.acquire(session.getId());                        // 3) 握手频次限流
    // 启动 10s 超时计时器，等首帧 agent.authenticate
    scheduler.schedule(() -> closeIfNoAuth(session), 10, SECONDS);
}

@Override
protected void handleTextMessage(WebSocketSession s, TextMessage m) throws Exception {
    AgentMessage msg = AgentMessage.fromJson(m.getPayload());
    rateLimiter.acquire(s.getId(), msg.type);                          // 4) 业务限流 (心跳12/min, metrics 24/min)
    switch (msg.type) {
        case AGENT_AUTHENTICATE -> authService.authenticate(s, msg);  // 5) 鉴权
        case HEARTBEAT           -> heartbeatService.heartbeat(s);   // 6) 心跳
        case METRICS_REPORT      -> metricsService.report(s, msg);   // 7) 指标入库
        case TERMINAL_OPENED, OUTPUT, CLOSED -> terminalAgentRelay.relay(msg); // 8) 终端上行
    }
}

@Override
public void afterConnectionClosed(WebSocketSession s, CloseStatus status) {
    connectionRegistry.remove(s.getId());                              // 9) 摘 session
    if (lastAuthServerId != null) {
        heartbeatService.markOfflineOnDisconnect(lastAuthServerId, lastHeartbeatAt); // 10) 乐观锁离线标记
    }
}
```

**乐观锁离线标记**关键片段（`AgentHeartbeatServiceImpl.markOfflineOnDisconnect`）：

```java
UPDATE servers
   SET agent_status='offline', last_heartbeat_at=:now
 WHERE id=:id AND last_heartbeat_at=:disconnectAt  -- 乐观锁：必须是断开时记得的时间戳
```

#### 3.1 状态机（`AlertStateMachine.java`）

```java
// module/alert/service/AlertStateMachine.java (核心 sealed interface)
public sealed interface Transition permits Trigger, ContinueBreached, Resolve, NoAction {}

public Transition evaluate(AlertStateEntity s, MetricSnapshot cur) {
    boolean breached = cur.breached();
    if (s == null && breached)        return new Trigger();          // 首次越界
    if (s == null)                   return new NoAction();          // 没越界、没历史
    if (s.active && breached)        return new ContinueBreached();  // 持续越界
    if (s.active && !breached)       return new Resolve();           // 恢复
    return new NoAction();
}
```

#### 3.2 评估（`AlertEvaluationServiceImpl`）

```java
@TransactionalEventListener(phase = TransactionPhase.AFTER_COMMIT)
@Transactional(propagation = Propagation.REQUIRES_NEW)   // 关键：必须显式 REQUIRES_NEW
public void onMetricsReported(MetricsReportedEvent ev) {
    List<AlertRule> rules = ruleMapper.selectEnabledForServer(ev.serverId());
    for (var rule : rules) {
        var transition = stateMachine.evaluate(stateMapper.find(rule.id, ev.serverId()), metric(rule, ev));
        switch (transition) {
            case Trigger t -> {
                Long recId = recordMapper.insert(new AlertRecord(rule, ev, "unread"));
                stateMapper.insert(new AlertState(rule.id, ev.serverId(), true, recId, 0));
                publisher.publishEvent(new AlertTriggeredEvent(recId)); // 二次 AFTER_COMMIT
            }
            case ContinueBreached cb -> stateMapper.touch(s.id(), s.version()); // 乐观锁 +1
            case Resolve r -> {
                recordMapper.markResolved(s.alertRecordId());
                stateMapper.markInactive(s.id(), s.version());
            }
            default -> {}
        }
    }
}
```

> **坑**：Spring 6.2 拒绝 `@TransactionalEventListener(AFTER_COMMIT)` + 默认 `@Transactional` 组合（默认 `REQUIRED`）。本项目显式 `REQUIRES_NEW`，确保监听器在新事务里执行而非外部事务，**避免回滚混乱**。

### 7. 可深入追问

1. **为什么需要"状态表 + 乐观锁 + 唯一索引"三件套？**

   - 乐观锁让并发评估只一条赢；

   - 三层防御，确保业务一致性。
2. **为什么 AFTER_COMMIT 而不是 BEFORE_COMMIT？** 事务回滚时不应推告警；AFTER_COMMIT 才能保证"写表成功 + 推送成功"是绑定的。
3. **为什么二次发布 AlertTriggeredEvent？** `MetricsReportedEvent` 是事务内的，告警评估要 REQUIRES_NEW（独立事务）；二次事件让 `AlertPushPublisher` 也走 AFTER_COMMIT 语义。

```java
@Transactional
public TerminalSession openSession(Long userId, Long serverId, String openMessageId) {
    requireApproved(userId);                                  // 1) 只有审核通过用户才能开终端
    if (!serverMapper.isAgentOnline(serverId)) throw AGENT_OFFLINE(40904);
    
    GlobalQuotaLock.lock();                                   // 2) 单 JVM 配额锁
    try {
        enforce(userRepo, serverId, userId);                  // 3) 用户≤2, 服务器≤4, 全局≤16
    } finally { GlobalQuotaLock.unlock(); }
    
    return sessionRepo.upsert(userId, serverId, openMessageId); // 4) (user_id, open_message_id) UNIQUE 幂等
}
```

状态机：`opening → open → closed/timeout/error`。

#### 3.4 三层限流

| 层 | 类 | 策略 | 阈值 |
|---|---|---|---|
| 输入控制帧 | `TerminalMessageRateLimiter` | JVM 内存 Token Bucket，按 `(Monitor Session, serverId)` 分桶 | open 6/min、input 600/min、resize 60/min、close 30/min；超限返 `42904 TERMINAL_MESSAGE_LIMIT_REACHED` 且不下发 Agent |
| 输出字节 | `TerminalOutputRateLimiter` | JVM 内存 Token Bucket，按 sessionId | 默认 256 KiB/s + 512 KiB burst；不够直接关 PTY |
| Agent 端输出 | Go `internal/terminal/output_limiter.go` | 同样 Token Bucket | 256 KiB/s + 512 KiB burst；不够即关会话 |

#### 3.5 配额锁（`TerminalGlobalQuotaLock`）

```java
public void enforce(...) {
    if (countDistinctActiveByUser(userId) >= 2) throw SESSION_LIMIT_REACHED(42903);
    if (countActiveByServer(serverId) >= 4)    throw SESSION_LIMIT_REACHED;
    if (countDistinctActiveUsers() >= 5)       throw SESSION_LIMIT_REACHED;
    if (totalActive() >= 16)                   throw SESSION_LIMIT_REACHED;
}
```

`ReentrantLock` 单 JVM（多 JVM 必须改 Redis 集中锁，本项目 v1 单实例）。

### 7. 可深入追问

1. **为什么三段链路而不是浏览器直连 Agent？** 浏览器无法感知 Agent（NAT / 防火墙），由 Java 中继做 NAT 穿透 + 鉴权代理。
2. **为什么 PTY 数据不入库？** 输入可能含密码，存盘违反审计最小原则 + 存储爆炸；元数据足够排障。
3. **为什么双层字节限流（Go + Java）？** 防止任一端被绕过 / bug 导致另一端失控。
4. **为什么用 `ConcurrentWebSocketSessionDecorator`？** Spring 6.2.8 原生背压，比手写 `ScheduledExecutorService` 可靠 10x。
5. **为什么 `shell_identifier` 只回 `bash` 不回 `/bin/bash`？** 防协议层泄露目标文件系统路径（多服务器多 bash 路径场景）。
